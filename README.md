## Repository workflow

1. Work on a descriptive task branch, such as `docs/member4-project-control`.
2. Commit coherent changes with messages explaining what changed.
3. Open a pull request into `main`, linking relevant existing tasks where applicable.
4. Record verification and material AI assistance, respond to findings, and obtain two meaningful approvals from team members other than the author.
5. Merge only after review requirements are met. Preserve approved baseline history and use reviewed changes for later revisions.

Use the [pull request template](.github/PULL_REQUEST_TEMPLATE.md) for documentation and later code changes. No application code, CI pipeline or production deployment is introduced for M1.
